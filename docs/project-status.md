# وضعیت پروژه — Plastic Products App

## پشته‌ی فنی
- بک‌اند: Django + DRF، روی main (worktree جدا در E:\plastic-products-backend)
- اندروید: Kotlin + Jetpack Compose، MVVM، Hilt، Retrofit+kotlinx.serialization،
  Coil، روی برنچ feature/android-scaffold
- Auth: OTP برای همه‌ی نقش‌ها + PIN دومرحله‌ای اختیاری برای ادمین

## فازهای تکمیل‌شده (۰ تا ۷، همه تست‌شده روی دستگاه واقعی)

| فاز | محتوا |
|---|---|
| ۰ | اسکلت پروژه، شبکه، DI، تم پایه |
| ۱ | Auth (OTP)، پروفایل |
| ۲ | مرور محصولات (لیست، فیلتر، جستجو، جزئیات، گالری تصویر) |
| ۳ | سبد خرید، ثبت سفارش، ویرایش/لغو سفارش خریدار |
| ۴ | جریان تحویل ویزیتور (تخصیص، تغییر وضعیت، اطلاعات تماس خریدار) |
| ۵ | تاریخچه‌ی سفارش خریدار، فاکتور PDF، اعلان‌ها، خروج از حساب |
| ۶ | مدیریت کامل ادمین (محصولات، کاربران/ویزیتورها، سفارش‌ها، گزارش‌ها/داشبورد) |
| ۷ | حالت‌های خالی/خطا/retry، دسترس‌پذیری، پرفورمنس، build نهایی (signing+R8) |

## فیچرهای اضافه‌شده بعد از تکمیل فاز ۷ (همه تست‌شده)
- change_phone حالا refresh_token واقعی برمی‌گرداند
- ویزیتور می‌تواند گزارش عملکرد شخصی خودش را ببیند (نه فقط ادمین)
- PIN دومرحله‌ای اختیاری برای نقش ادمین (admin_pin، endpoint های
  verify-admin-pin/set-admin-pin)، UI کامل (صفحه‌ی ورود PIN + بخش
  تنظیم PIN در پروفایل)
- Splash screen + لوگوی برند (کالیگرافی طلایی روی تیل)
- آیکون‌های Material واقعی، آیکون اپ سفارشی، گرید دو‌ستونه‌ی محصولات
- اشتراک‌گذاری محصول، پینچ-زوم گالری تصویر، Skeleton loader،
  transition بین صفحات
- دکمه‌ی پروفایل برای ادمین و ویزیتور (که در فاز ۶ فراموش شده بود)

## فیکس‌های بک‌اند کشف‌شده و انجام‌شده در طول توسعه (مرجع برای رفتار مشابه)
- verify_otp رفرش‌توکن واقعی برنمی‌گرداند (login/register، بعداً change_phone) → فیکس شد
- MultipleObjectsReturned روی OTP قدیمی منقضی‌شده → فیکس شد
- RestrictedError خام (۵۰۰) موقع حذف محصولِ استفاده‌شده در سفارش → ۴۰۰ تمیز
- لیست محصولات ادمین محصولات غیرفعال را نشان نمی‌داد → پارامتر include_inactive
- image_urls مسیر نسبی برمی‌گرداند (سریالایزر + upload_image جدا) → build_absolute_uri
- ساخت ویزیتور با شماره‌ی تکراری → IntegrityError خام → اعتبارسنجی تمیز
- edit_items با مقدار غیر-صحیح کرش می‌کرد → Decimal صریح + اعتبارسنجی
- تاریخ فاکتور PDF میلادی بود → با jdatetime به شمسی تبدیل شد
- visitor_performance فقط برای ادمین بود → ویزیتور هم رکورد خودش را می‌بیند

## محدودیت‌های شناخته‌شده (عمداً به تعویق افتاده)
- phone روی مدل User از نظر فنی از طریق PATCH پروفایل قابل‌تغییره — گپ امنیتی سبک
- تاریخچه‌ی قیمت/موجودی بدون فیلتر سمت سرور (فیلتر سمت کلاینت)
- change_phone هنوز UI اختصاصی در اپ ندارد (فقط backend فیکس شده)
- اپ تک‌مستأجره (single-tenant) — برای فروش به کارخونه‌ی دوم یا دسته‌بندی جدید نیاز به بازطراحی
- بدون درگاه پرداخت
- امتیازدهی به ویزیتور (rating) پیشنهاد شد ولی برای نسخه ۲ به تعویق افتاد
